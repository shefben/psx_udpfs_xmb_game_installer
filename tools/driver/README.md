# HDD driver: reproducible source build of ps2hdd-hdl.irx

The installer embeds `vendor/irx/ps2hdd-hdl.irx`. It is **built from
source**, not binary-patched.

## Why a change was needed

HDLGameInstaller's APA driver refuses to remove any partition whose
name starts with `__` (`apaRemove()` in `apa-hdl/src/hdd_fio.c`):

```c
if(id[0]=='_' && id[1]=='_')
    return -EACCES;
```

Hidden HDL game partitions are named `__.<ID>..<TITLE>`, so with the
stock driver an installed game could never be deleted from the console.

## Reproduction (done, byte-identical)

| Input | Value |
|---|---|
| Driver source | HDLGameInstaller `cdc6636` (v0.816, the commit that added `irx/ps2hdd-hdl.irx`); its `apa-hdl/` is identical to `ec37c81` |
| PS2SDK source (libapa, dev9/atad headers) | `1de4bd8` (last commit before 2018-06-18). Every PS2SDK revision 2018-01 .. 2018-06 gives the same binary. |
| Toolchain | Docker image `ps2dev/ps2dev:v1.0` (pinned by HDLGameInstaller's own CI), IOP GCC 3.2.3, plus `make`/`patch` from apk |
| Unmodified build | `58b217e93ebaf8b452d948fbde64a324ade6992484e22cc76b9d7aa99b547d15`, 31457 bytes |
| Vendored upstream IRX | `58b217e93ebaf8b452d948fbde64a324ade6992484e22cc76b9d7aa99b547d15` - **identical** |

`make driver` repeats this: it builds the unmodified source, refuses to
continue unless the result equals the vendored IRX, then builds the
patched variant into `vendor/irx/ps2hdd-hdl.irx`.

## The source change

`patches/apa-hdl/0001-allow-removing-hidden-hdl-games.patch` replaces
the `__` test with two checks from `tools/driver/remove_policy.h`:

* name: a `__` name is removable only if its third character is `.`
  (`__mbr`, `__net`, `__system`, `__sysconf`, `__common`, ... stay
  protected);
* type, after the partition is looked up: a `__` partition is removable
  only if its APA type is HDL (`0x1337`) - so `__.linux.N` and any
  non-HDL `__.` partition stay protected.

Names not starting with `__` behave exactly as before. Rename
protection of `__` names is unchanged.

`patches/apa-hdl/0002-allow-renaming-hidden-hdl-games.patch` applies the
same two checks to `apaRename()` (old name), which upstream refuses for
every `__` name. The installer shows a verified game in the XMB by
renaming its HDL partition `__.X` to `PP.X` (PFS-BatchKit-Manager's
layout), and hides it again with the reverse rename. System partitions
stay protected exactly as for removal.

Result: `f14fed88d134145f33f8d61ffe339c3b037f4c9da1118b0064126691c7ee3d0b`
(31657 bytes), pinned in `driver.env`. The build checks this hash
(`make driver-check`, run before every installer build).

The installer applies a stricter rule on top
(`partition_remove_allowed()` in `src/partname.c`): only a game-shaped
`__.XXXX-NNNNN..TITLE` partition of type HDL, a game-shaped `PP.`
channel of type PFS, the installer partition (`PP.UDPF-00001..INSTALLER`, formerly `PP.UDPFS-INSTALLER`) and `PP.UDPFS-TEST`.

## Evidence kept in the repository

* `docs/driver/apaRemove-upstream.txt`, `docs/driver/apaRemove-patched.txt`:
  disassembly of every `'_'` comparison in each binary (with its
  SHA-256), regenerated by `make driver`.
* `test/host/test_driver.py`: pins both hashes, checks the patch removes
  only the original `__` test, and that the committed disassembly
  matches the binaries.
* `test/host/test_policy.c`: compiles `remove_policy.h` unchanged and
  tests `__.SLUS-xxxxx..GAME` (HDL) deletable; `__common`, `__mbr`,
  `__sysconf`, `__net`, ... not; `__.linux.1` and PFS-typed `__.` names not.

Hardware status: the patched driver has not yet run on a DESR.
